# Flagship Starter Pack One

Prompt: C2

Status: complete; C2B audit next

## 1. Scope

C2 adds the `Local Rules, Global Patterns` flagship collection over four existing production templates. It adds four focused runnable Starter Worlds, eight strict launch recipes, four derived prepared comparisons, one collection route, recipe-aware World context, and one bounded Forest Fire initialization preset.

## 2. Product Purpose

The pack demonstrates that one implemented template can support several model-specific investigations without inventing mechanics. Each world offers a baseline and contrast whose differences are named, validated, and worth inspecting through existing outputs.

## 3. Collection Theme

The collection asks how local noise, spatial starting structure, starting population pressure, and connected paths can reorganize aggregate model behavior. The four templates remain mathematically distinct; membership does not imply a shared equation or universal mechanism.

## 4. Pack Artifact

`StarterWorldPackDefinition` is strict version-1 content metadata in `src/lib/starterWorlds/packs/`. It references at least two runnable worlds, validates membership and a featured world, rejects duplicate IDs, slugs, world references, and unsafe keys, and is recursively frozen. It contains no executable code, RunConfig, hidden runtime defaults, persistence, or progression state.

## 5. Recipe Artifact

`StarterWorldLaunchRecipe` is strict version-1 data. Each recipe names one Starter World, production template, allowed initialization preset, bounded parameter overrides, optional preset-owned options, a string seed, supported task, run horizon, existing metric IDs, and a model boundary. Canonical recipe handoffs contain only `starter` and `recipe` IDs; World re-resolves both before scenario construction.

## 6. Prepared-Comparison Artifact

`PreparedStarterComparison` is strict version-1 instructional content. Its controlled differences and shared conditions are generated from validated effective recipe scenarios rather than accepted as authored claims. Both recipes must belong to one world, use one template, declare opposite roles, and reference outputs available to both.

## 7. Runtime Boundaries

Valid pack content is not runtime support. Recipes use existing scenario services and template contracts; comparisons do not execute, auto-run, save, or infer results. Every handoff creates a fresh paused tick-0 scenario. C2 adds no engine primitive, scheduling change, arbitrary formula, arbitrary code, generic scenario composition, or capability flag.

## 8. Coordination Under Sensor Noise

This focused Collective Motion world compares `Clear local signals` with `Noisy local signals`. Both use Random Headings, seed `c2-coordination-001`, and identical effective configuration except Noise, which is `0.01` versus `0.28`. Users compare Alignment score, Dispersion, and visible subgroup formation. The world is not animal-behavior validation, vehicle-safety evidence, or controller optimization.

## 9. Clustered Outbreak Starts

This focused Local Contact Outbreaks world compares `One concentrated cluster` with `Several separated hotspots`. Both start nine infected model agents with seed `c2-outbreak-001` and equal transmission, recovery, population, and movement parameters. The initialization preset and preset-owned spatial options differ. Users compare Infected and Recovered histories plus visible pocket coalescence. It is not a forecast or public-health advice.

## 10. Predator Pressure and Recovery

This focused Predator-Prey Cycles world compares `Recovery margin` with `High predator pressure`. Both use Random Ecology, 160 initial prey, seed `c2-predator-001`, and unchanged encounter, mortality, reproduction, and movement mechanics. Initial predators are `2` versus `12`. Users compare Prey and Predator counts, zero-count states, cycle timing, and visible recovery or collapse inside the model.

## 11. Patch Density and Firebreaks

This focused Landscape Spread world compares `Connected fuel` with `Firebreak corridor`. Both use a central ignition, full fuel apart from the corridor, seed `c2-firebreak-001`, closed boundaries, von Neumann neighbors, and spread probability `1`. The contrast inserts one full-height column of the existing empty-cell state. Users compare Active fires, Burned cells, extinction, and visible crossing.

## 12. Scenario and Preset Additions

C2 adds only `firebreak-corridor` to the Forest Fire template. Existing presets could lower global density but could not honestly represent a continuous barrier. The new preset uses the existing initialization pipeline, empty/fuel/burning states, central ignition, seeded runtime, and local spread rule. It changes no parameter definition, default, bound, metric, intervention, scheduler, engine service, or capability claim.

## 13. Comparison Semantics

Prepared pairs are configuration guidance. A user may run the baseline, explicitly save the existing bounded World comparison summary, run the contrast for the same horizon, and inspect the existing difference view. C2 does not create another comparison system, auto-save a run, or change `ortus.runComparison.v1`.

## 14. Research Boundaries

Sources connect each world to relevant research or historical context. They do not calibrate, validate, predict, prove causality, establish robustness, or turn model output into empirical evidence. Terms such as emergence, criticality, resilience, phase transition, and policy effectiveness are not inferred from a prepared pair.

## 15. Persistence Boundaries

C2 adds no storage key. Pack, recipe, comparison guidance, catalog state, and nudge dismissal remain content, URL, or mounted-page state. Existing bounded World comparison storage is unchanged and does not become Lab evidence, an Atlas discovery, learning progress, or curriculum state.

## 16. Non-Goals

C2 does not implement C2B, C3, progress tracking, profiles, achievements, analytics, recommendations, AI-generated content, Lab or Atlas persistence, general resource or multiscale runtime, new metrics, new interventions, arbitrary formulas, arbitrary code, custom-model execution, or Tier B/C portfolio candidates.

Prepared outcomes remain seed- and configuration-specific model behavior.
