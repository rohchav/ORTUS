# Starter Remix Bridge

Status: S1 COMPLETE; S1B NEXT / UNSTARTED

This record documents the bounded executable-authoring bridge implemented by S1. It is subordinate to `../CAPABILITIES.md`, `../ARCHITECTURE.md`, `../SCIENTIFIC_MODEL.md`, and `../ROADMAP.md`.

## Implemented Flow

```text
immutable Starter or prepared recipe
  -> strict ID-only Remix request
  -> authoritative Starter scenario
  -> unsaved derivative draft
  -> supported configuration edits in Workshop
  -> explicit validation and Run Remix
  -> established World runtime path
```

Starter detail, prepared recipe, and matching active World contexts expose deterministic Remix entry. The source configuration arrives preloaded; users do not reconstruct it manually. A product-authored Starter question may focus the relevant existing parameter, but no natural-language generator or hidden model mutation exists.

## Coverage

All eleven current runnable Starter World definitions classify as category A against existing executable contracts. Seven support their direct Starter launch. The four `Local Rules, Global Patterns` worlds retain eight strict baseline/contrast recipe launches. No category B or C source exists in the current catalog, and S1 does not weaken launch checks to manufacture coverage.

This classification means configuration-level remix support only. It does not mean eleven runtime families, general model authoring, or structural composition.

## Editable And Fixed

Workshop reads the authoritative template, scenario, initialization, and validation contracts. Depending on the selected template, an S1 draft can edit:

- seed;
- template-defined numeric parameters;
- supported initialization preset and options;
- supported behavior mode;
- supported agent composition;
- supported environment options.

S1 keeps these fixed:

- template/model family identity;
- entity and state structure;
- processes, interactions, and executable rules;
- spaces and graph topology except existing bounded options;
- metrics and interventions;
- schemas, Builder graphs, formulas, scripts, and code.

The default Guided and Advanced Workshop experiences remain structural and non-executable. S1 does not create a parallel parameter registry, compile `ModelSchemaDefinition`, execute visual-builder edges, or implement S2/S3 composition.

## Draft, Launch, And Authority

The canonical Starter registries remain recursively frozen. Remixing creates a new validated scenario with explicit source and derivative identities. Edits are local candidate values until the user selects Run Remix. Invalid values remain visible in the draft, disable launch, and cannot mutate the source, active World, accepted run, Worker, comparison, template, or schema artifacts.

Run Remix uses the existing scenario application path. `flocking-boids` remains the only Worker-capable runtime template and keeps one Worker-owned engine, scheduler, tick accumulator, and seeded RNG authority. Starter recipes backed by `flocking-boids` use that same authority. The other six production templates retain their existing main-thread engine path.

## Lineage, Reset, And Lifetime

Run details distinguish:

```text
Source Starter -> Unsaved remix -> active run
```

The derivative never claims to be the untouched prepared source. Reset of an accepted Remix rebuilds the same seed, supported configuration, scenario identity, and source lineage at tick zero while discarding run progress. Generic prepared-source Reset retains its established rule of dropping prepared provenance.

Drafts are page-session state, not durable models. Strict URLs contain source and derivative IDs, never editable payloads. An active World transfer uses one bounded, matching, accepted-config-only in-memory handoff. Back/Forward and source changes create fresh draft identity; reload of an unsaved World derivative fails closed instead of substituting the source Starter or a generic run.

## Interaction Evidence And Limits

The core flow is keyboard-operable without drag-only or hover-only steps. Controls expose grouped labels, associated errors, focus-managed leave confirmation, semantic status, and responsive layouts. Automated Chromium/Axe coverage is not direct screen-reader, assistive-technology, forced-colors, browser-zoom, touch-device, formal WCAG, or human-comprehension evidence. The UR0 human comprehension gate remains pending.

## S2 Handoff Gaps

Current Remix remains field-oriented and tied to existing templates. It cannot add or remove entities, state, processes, relations, spaces, rules, metrics, or reusable blocks; manipulate structure visually; compose model parts; define a new model family; or construct a model from an open question. S2 must inherit these observed constraints, preserve the executable-versus-structural boundary, and wait for S1B before becoming next.

S1B must independently audit source immutability, lineage, candidate/accepted isolation, both runtime paths, reset and navigation semantics, keyboard/responsive behavior, and capability language before S2 begins.
